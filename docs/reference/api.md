# API Reference

Generated from the routers by `mix optimal.api.reference`.
Do not edit this file by hand: change a route, then run the task, and CI fails when the two disagree.

Every route below is served under `/api`.
A request carries `Authorization: Bearer oe_<id>_<secret>` unless the Engine runs with `OPTIMAL_AUTH_REQUIRED=false`.
With `OPTIMAL_AUTH_REQUIRED=true` every route refuses a request without a valid key, health and version included.
Authentication, workspace scope, and operation grants are enforced by `OptimalEngine.API.PermissionPlug`; `read` and `write` cover ordinary operations, while administration, app-data schema changes, claim review, and authority operations require their own grant.

Grant is the operation grant the key needs (alternatives joined by `or`), read from `OptimalEngine.API.PermissionPlug`.
Workspace is `workspace` when the route is authorized for the workspaces it names (the implicit `default` when it names none), and `tenant` when it is tenant-wide; read from `OptimalEngine.API.WorkspaceAuthPlug`.
A key whose metadata grants app data access (`/api/data/keys`) is confined to `/api/data` whatever its grant.
`GET /api/sync/tables` returns `replicated`, `local_only` and `migration`; a relay treats every table that is not in `replicated` as local, and `local_only` is not exhaustive (a table another version adds is in neither list).
`GET /api/authority/evidence/export` takes `after`, `limit` (at most 10,000), `until` and `format` (`json`, or `ndjson`: each entry on a line with `"type": "entry"`, then an `export_end` line with `head`, `head_signature`, `total`, `complete` and `next_after`), and returns `entries`, `head` (`{"seq", "hash"}` of the chain's last entry or the entry at `until`, `null` for an empty chain), `head_signature`, `total` (the chain from seq 1 through the head, the same on every page), `complete` (true only on the page ending at the head) and `next_after`; an `after` or `until` that is not a signed 64-bit integer, or an `until` beyond the head or below `after`, answers 400, and `docs/guides/optimal-authority.md` has the paging rule.
`GET /api/authority/evidence/keys/:kid` returns one evidence key of the tenant as a public JWK (`kty`, `crv`, `kid`, `x`, `alg` `EdDSA`, `optimal_purpose` `evidence`, and `retired_at` in ISO 8601 UTC when the key is retired); a kid that is unknown, a grant key's or a revoked key's answers 404.
`GET /api/search` returns each hit's whole text in `content` by default; `content=snippet` returns the first 600 bytes instead, beside the `l0_abstract`, and `content_truncated` (in both shapes) says whether text was cut. `GET /api/read?tier=full` reads one document whole. A document is one result: hits with the same URI, and a signal with its cross-reference copies (`metadata.cross_ref_of`), collapse to the best ranked. A workspace nothing was written to answers an empty list (a registered workspace of another tenant answers 404).
`GET /api/graph` returns the whole workspace unless `limit` (at most 200) is given; `limit` and `offset` then window the contexts, the edges are those between the contexts of the window, and the entities number at most `limit`. An `offset` without a `limit` skips that many contexts and returns the rest, with only the edges between them, and every entity. `stats` always reports the whole workspace and `pagination` the window (`limit` is null when none was given).
`GET /api/batch/export/signals`, `/memories` and `/workspace` return everything the caller may see unless `limit` (at most 200) is given; `limit` and `offset` then window the list, oldest first. `pagination` is in every answer (`limit` is null when none was given), and `complete` is false while rows were withheld or the window stops short of the end.
`GET /api/stats` counts one workspace in the caller's tenant (the one named by `workspace`, else `default`), names it in `workspace_id`, and keeps `cache_size` as 0 (the cache belongs to the process, not a workspace).

A key's metadata may carry `allowed_security_labels` and `allowed_partitions`, the labels and partitions it may read.
The routes that return row text in bulk (`/api/batch/export/*`, `/api/sync/conflicts`, `/api/storage/workspaces/:workspace_id/mutations`) show a key only the rows its grants cover, by the rule of governed retrieval, and say what they left out in `withheld` and `complete`.
A grant of `"*"` means all of its kind.
The bootstrap key holds it when its scopes include `*` or `admin`; a key minted without grants holds none.
A key without a `"*"` label grant is also not shown rows above the Engine's ceiling for what it hands out (`sync_serve_max_class`, default `confidential`) by the exports and the conflict list.
The recommended grants for a machine key are `{"allowed_security_labels": ["public", "internal", "confidential"], "allowed_partitions": []}`.
`docs/guides/replication.md` has the rule and the routes it does not cover yet.
